# Documentation Conventions

- Keep documentation close to the code or decision it describes.
- Comments should explain why, constraints, or non-obvious behavior instead of restating obvious code.
- Keep README files focused on setup, usage, architecture entry points, and repository-specific guidance.
- Put durable engineering standards in `docs/conventions/`.
- Put implementation history and rationale in `docs/changes/`.
- Update documentation when behavior, configuration, APIs, architecture, or operational requirements change.
- Remove stale documentation when it becomes incorrect.
